Settled through the [Bilingual Interface and Cluster Views map](map.md) (wayfinder, 2026-10-27 to 2026-10-28). Each decision below is the current state of its ticket, with every later amendment already applied. When this spec and a ticket's original Answer disagree, the spec wins, and the ticket's Comments record the amendment. Glossary: [CONTEXT.md](../../CONTEXT.md) (**Interface Language**, **Edge Appearance**, **Connection Ratio**, **Connection Share**). Records: [ADR 0003](../../docs/adr/0003-bulgarian-is-a-view-only-translation.md) (the translation), [ADR 0004](../../docs/adr/0004-connection-ratio-is-the-configuration-model-ratio.md) (the measure). ## Goal

The Tag Network app gains four features:

1. **Interface Language**: an EN | BG switch that shows the whole interface (Workbench, Analysis Report mode, Parameter Selection) and the User Guide in English or Bulgarian.
2. **Edge Appearance**: the user sets how links are drawn: width, scaling, colour, strength, the strength of links between Clusters, and a view-only threshold below which links are not drawn.
3. **Cluster connections**: the size-aware **Connection Ratio** and the directional **Connection Share** between Clusters. They are explorable as a matrix, as a floating map and pair by pair.
4. **Games within a Cluster**: the games that have a Cluster's Tags, ranked by how many they match.

**The hard rule: no scientific change.** No Network State, `state_id`, Cluster, metric, Parameter Selection result or cache key changes. Language and Edge Appearance are view choices, like the existing "show shared games" switch. They are never part of the Network State, an export or any number. Features 3 and 4 only read the Network State on screen. New columns and tables are additive and never redefine an existing one.

## Decisions

### Scope

- **In**:
  - the four features, in the Workbench, in both the Global and the Cluster-separated layout;
  - Edge Appearance also in Analysis Report mode, which draws the same canvas;
  - translation of every visible string in all three modes: errors and warnings, generated explanations (the Network State sentence, the quality lines, "Why this pair", the loading panels), tooltips and help;
  - a Bulgarian copy of the whole User Guide;
  - the English guide entries for the new features;
  - the additive export changes.
- **Out**: see [Out of scope](#out-of-scope).
- **No new runtime dependency** (ADR 0001): no gettext, no Babel, no new JS library.

### Interface Language

#### The switch and its persistence

- An **EN | BG** segmented control sits in the header, beside the mode switch, in all three modes. English is the default.
- The choice is kept per browser in a cookie, `steamstudy_lang`, written client-side. Cookies ignore the port, so the choice survives restarts and `--port` changes.
- `app.layout` becomes a function that reads the cookie when the page is served, so the first paint is already in the chosen language. A `lang` store holds the language from then on.
- **Switching is live, never a reload**:
  - `build_layout` records each translated static prop as (component, prop, message) in a registry. One relabel callback sets them all with `set_props`, so a new static label needs no new wiring.
  - Callbacks that render text take `lang` as an Input. Callbacks that compute numbers take it only as State, so a switch never recomputes a Network State.
  - Running jobs carry on. Their progress is raw numbers rendered in `ps_view`, so it re-renders in the new language.
  - The browser tab title is relabelled client-side: Tag Network / Мрежа от тагове.

#### Catalogue and translator

- **Catalogue**: plain Python dicts **keyed by the English text**, with named `{placeholders}` only. Bulgarian lives in one module per area under `steamstudy/i18n/bg/`, for example `layout.py`, `view.py`, `ps_view.py` and `selection_text.py`.
- **Translator**: `tx = text(lang)` is an explicit, **required** argument of every function that renders visible text: `view`, `ps_view`, `selection_text`, `help` and `ps_run.eta_text` / `elapsed_text`. It offers:
  - `tx("…", **values)`;
  - `tx.n(count, one=…, other=…, **values)` for counted messages;
  - `tx.join(items)` for list joining;
  - `tx.num(value, digits)`.
- **Exports and the CLI pass `text("en")`**: `ps_export`'s `selection_report.md`, `bundle/make.py`, and every other caller outside the screen. There is no process-wide setting and no contextvar.
- **Missing entries fall back to English at runtime**, with no error on screen.
- An edited English string changes its key on purpose. The catalogue parity test then fails until the Bulgarian is updated, once the module is on the done-list (see [Strictness ratchet](#strictness-ratchet)).

#### Plurals and numbers

- **Plurals**: a counted message is two whole forms, `one` and `other`, with the verb agreement inside each form. No `(s)`, `is/are` or `has/have` stitching is left in code. The Bulgarian `other` form is written in the count form (`{n} тага`), because the numeral always comes first.
- **Numbers on screen**: one rule per language, owned by `tx.num()`.
  - `tx.num()` replaces `view.num()` and also translates `n/a`, `yes` and `no`.
  - The `selection_text` helpers (`_pct`, `_range`, `_signed`) use `tx`.
  - English is unchanged from today. Bulgarian has a decimal comma, no thousands separator and an attached `%`.
- **The rule is mirrored in three places**:
  - the grids' `d3.formatLocale({decimal, thousands})`, with the column definitions re-sent on a switch;
  - Plotly `layout.separators`;
  - `pills()`, through `ui-words`.
- **Exports never call these**, so no exported number can change.

#### JS, CSS and third-party widgets

- **JS and CSS hold no words**:
  - A `ui-words` store gives `workbench.js` and `graph.js` the pill words, the tooltip footer, the ⓘ `aria-label` and the words of the new cards.
  - The CSS `" copied"` becomes `content: attr(data-copied)`.
  - Tooltips reach JS as structured `[kind, text]` lines, so `TIP_LABEL` goes away.
- **Third-party widgets**: only what a widget exposes as an option is translated:
  - ag-grid `localeText` (just the strings our grids show);
  - our own Plotly titles and hover text;
  - the Dropdown placeholder and search props.

  The Plotly modebar and any built-in text without a prop stay English.
- **Open Network State refusals**: `OpenRefused` carries a reason code plus parameters, and `callbacks.py` renders `Refused: …` through `tx`. Terminal and CLI errors stay English.
- **Schema `description` header tooltips** (identifier columns) are translated on screen through the catalogue. `export/schema.py` and every export keep the English text.
- **Never translated**: Steam tag names, game titles, Steam Genre values, cluster labels `C1…`, the five dataset labels, export column and file names. Grid headers are column names, so they stay English.

#### The Bulgarian User Guide

- `docs/user-guide/bg/` is a parallel copy with the same file names. The English guide is unchanged.
- **Heading ids**: every Bulgarian heading ends with `{#<english-slug>}`. The parser strips the id from the shown heading and uses it as the anchor. `help.HELP`, `PANEL_SECTIONS`, `ENTRY_BY_COLUMN` and every in-guide `file.md#anchor` link stay language-independent. A lookup becomes (lang, file, anchor). A Bulgarian file, section or anchor that doesn't exist yet falls back to the English one.
- **In short labels and entry markers**: one label set per language. `in_short()` and `in_short_problems()` take the language's set, with the same 60-word cap. The Bulgarian labels are in the term table's **Guide labels** section.
- **Appendix B** is generated a second time by `export/column_index.py`, with Bulgarian fixed labels, into `bg/appendix-b-column-index.md`. The staleness test checks both files.
- The `bg/` copy ships in the wheel and the App Bundle with no packaging change.
- **The guide documents the switch**: `02-app-controls.md` gains an **Interface language** entry in the Control reference. It covers the switch, what stays English (exports, tag names, dataset labels) and the cookie.

#### Tests

- **Catalogue parity** (AST scan of `src/steamstudy/app`, `network/selection_text.py` and `app/export.py`'s refusals):
  - every `tx("…")` / `tx.n(…)` literal has a Bulgarian entry;
  - placeholder names match;
  - counted messages have both forms;
  - no Bulgarian key is orphaned.

  Text that reaches `tx` as a variable is checked through a declared list of its sources: the schema descriptions shown as header tooltips, the `OpenRefused` reasons and the In short label sets.
- **Guide structure parity**:
  - each English heading id has a Bulgarian twin at the same level in the same file;
  - Bulgarian links resolve;
  - each entry has the same In short labels in the same order and the same markers.
- **Verbatim per language**: the `selection_text` sentences rendered with `text("bg")` appear verbatim in the Bulgarian guide.
- **English only**:
  - the ~70 app phrase asserts;
  - the five English content tests: interpretation bands, Hennig, never-cited sources, required statements and limitations.
- **Correctness** checks are strict from the start: placeholders, plural forms, orphans, heading levels and link resolution, wherever Bulgarian exists. **Completeness** checks (a missing entry or heading) follow the ratchet below.

### Bulgarian terms and numbers

[docs/i18n/bg-terms.md](../../docs/i18n/bg-terms.md) is the rule for every Bulgarian text. It sits outside `docs/user-guide/`, so the guide parser and the parity tests never read it. Its policy, in brief:

- Translate by default. Proper names and abbreviations stay in Latin script: Leiden, Jaccard, ARI, γ.
- Export columns and files appear in English, in backticks.
- Each Bulgarian guide entry heading gives the English term once, e.g. `### Лифт (Lift) {#lift}`.
- The guide uses lowercase polite *вие*. Buttons use the short imperative.
- Dataset labels stay English, on screen too.
- Bulgarian numbers on screen: 0,42 · 12345 · 42%.

The terms introduced by features 2–4 (Connection Ratio, Connection Share, Edge appearance, Connections matrix, Cluster map, pair view, Games section, Matched, "of its tags") get rows before the bulk translation starts (issue 22).

### Edge Appearance

- **Form**: the legend's thickness key. It is collapsed by default to today's one-line key plus an "Edges" toggle.
  - Expanded, it is a card with a histogram of the drawn measure's values per link, the drawn width ramp over it, and the controls.
  - The card floats as a transient overlay (`data-graph-transient`, like the floating Inspector). Opening or closing it never changes the canvas area, the layout or the fit.
  - When the appearance is not the default, the collapsed key says so, e.g. "Edge thickness: shared games (√, 0.5–4 px) · 12 hidden".
- **Controls** (each stepper's tooltip shows its current value, in the Interface Language's number format):
  - **Width ±** multiplies both ends by 1.25. The minimum stays within 0.1–3 px and the maximum within 1–12 px. Default 0.4–3 px.
  - **Scaling**:
    - linear (default; today's 0.4 + 2.6 × value / largest);
    - square root, √(v / largest);
    - log, log(v / smallest) / log(largest / smallest).

    There is no rank scaling.
  - **Colour**:
    - one colour (default `#8d95a3`);
    - **By Cluster**: links within a Multi-Tag Cluster in its colour, other links neutral;
    - **within vs between Clusters**: slate and orange;
    - **by value**: a ramp from `#c9ced8` to `#3b2f6b`, kept away from the selection blue `#2457d6`, and checked against both themes.

    A tag's selected links keep their colour mode and only become opaque. Under one colour they darken, as today.
  - **Strength ±**: opacity × 1.35, within 3–100 %. Default 18 %.
  - **Links between Clusters ±**: opacity × 1.5, within 0–100 %. Default 6 %. It is shown and applied only in the Cluster-separated layout.
  - **Show shared games** moves into the card's header. It is still offered only under Lift, and still unticks when the Clustering Weight changes.
  - **Hide links below** is a handle on the histogram.
- **Hide links below**:
  - A hidden link is not drawn, cannot be tapped and does not light up in a tag's neighbourhood highlight.
  - It still counts in the Inspector's connected tags, the Edges table and every number. A tag whose links are all hidden stays drawn.
  - The card always shows "N links hidden from the drawing" and names **Minimum shared games** as the separate filter, the one that is part of the Network State.
  - The threshold is in the drawn measure's units. It clears when the measure (the Clustering Weight or the show-shared switch) or the dataset changes. It is kept across other Network State changes, and the count updates. With no link below it, the card shows "0 hidden".
  - It never persists.
- **Scope**: one appearance for both layouts and for Analysis Report mode. **Reset all** never touches it. The card's own reset returns to today's look.
- **Persistence**: the look (width, scaling, colour, the two strengths) is kept per browser in a cookie, `steamstudy_edges`, written by `graph.js`. It is the same mechanism as the Interface Language. Browser storage was rejected because it is kept per origin, so the look would be lost whenever the port changed.
- **Architecture**:
  - The `graph-data` payload carries each edge's raw `shared`, `lift` and `intra` instead of `width`.
  - `graph.js` owns the appearance state. It computes width, colour and hiding by restyling the elements already drawn.
  - The show-shared switch becomes browser-only and stops re-sending the payload, which it does today through `render_graph`.
  - `renderer.py` keeps the defaults and the legend wording.
  - No appearance setting reaches Python, a Network State, an export or a cache key.
- **Guide**: in `02-app-controls.md` the **Edge thickness** entry becomes **Edge appearance**, with a paragraph per control.
  - Each control's tooltip points to its paragraph.
  - The old `edge-thickness` anchor stays as an alias, so existing links resolve.
  - The caution "never compare thicknesses across the two measures" stays.

### Connection Ratio and Connection Share

The measures; their look is in [Cluster connections view](#cluster-connections-view).

- **Connection Ratio**: r_ab = w_ab / (k_a·k_b / 2m), in the Clustering Weight.
  - k_a is the Cluster's strength (2·`internal_weight` + `cut_weight`), and 2m = 2·`total_weight`. All are sums over existing per-tag values.
  - 1 means the weight the two strengths alone predict. The ceiling is γ, the merge test Louvain and Leiden already pass, so a value near γ marks a pair that almost merged.
- **One-Tag Clusters**: the existing `one_tag_pool` grouping stays.
  - k_p is the sum of its members' strengths.
  - The pool–pool expectation is over distinct pairs, E_pp = (k_p² − Σ_i k_i²)/4m, so the γ ceiling holds on pool rows too.
- **Connection Share**: w_ab / cut_a. It is directional, so each pair has two values, and a Cluster's shares sum to 1.
  - It is computed in the Clustering Weight only, with no shared-game twin.
  - For the pool, cut_p = k_p − w_pp (all link weight touching the pool's tags, pool–pool links counted once), so the pool's shares also sum to 1.
- **Both totals, always**: a shared-game total is always filled. It equals `weight` under shared games and is the second total under Lift. With it comes a **shared-game ratio**, computed from shared-game sums and shared-game strengths. Under Lift it is labelled "not tied to the clustering; can exceed γ".
- **Edge values**: shown as computed, never clamped. A ratio a hair above γ (Louvain's 1e-7 gain tolerance) is shown as it is, and the guide says why. The cell is empty where a denominator is zero:
  - a pool of isolated tags only (k_p = 0);
  - a pool–pool row with fewer than two linked pool tags (E_pp = 0);
  - a Cluster with no outside links (cut_a = 0), whose shares are empty.

  There is no status column. The guide lists the three cases.
- **Reading**: the ratio is a plain number with γ beside it, and the two reference points (1 and γ) are in the text. No colour bands, labels or thresholds. The guide gives r/γ as the way to compare across resolutions; r/γ is not a column.
- **Not used**: density, pairwise Ncut, ΔQ_ab, game-set Jaccard, cluster Lift and PAGA ([ADR 0004](../../docs/adr/0004-connection-ratio-is-the-configuration-model-ratio.md)).
- **`cluster_connections.csv`**: the four existing columns are unchanged. Five new columns follow, in this order:

  | Column | Type | Meaning |
  |---|---|---|
  | `shared_weight` | float | the pair's total in shared games |
  | `ratio` | float | the Connection Ratio in the Clustering Weight; empty where undefined |
  | `shared_ratio` | float | the ratio from shared-game sums; equals `ratio` under shared games |
  | `share_of_a` | float | w_ab / cut_a; empty when cut_a = 0 |
  | `share_of_b` | float | w_ab / cut_b; empty when cut_b = 0 |

  Each column is declared in `schema.py` and indexed in `guide_index` and Appendix B. Full precision; no clamping.
- **Guide** (`03-metric-reference.md`): the **Cluster connections** entry keeps its anchor and gains the new columns. Its example becomes "seven links whose shared-game counts sum to 58", with a caution: w_ab sums shared-game counts over tag pairs, so one game can count several times (3 tags in C1 and 2 in C2 add 6). That is a wording change only, and no number changes.
  - Two sub-entries, **Connection Ratio** and **Connection Share**, each with its own anchor for tooltips. Each follows the standard In short / Higher → / Here / Caution layout, then Why it matters, Example, Bounds, Compare with and Exact definition.
  - Connection Ratio, as agreed:
    - *In short:* how much link weight joins two clusters, compared with what their total link weight alone would predict.
    - *Higher →* more connected than their sizes explain; 1 = exactly as predicted; the most it can reach is the resolution γ, and a value near γ means the two almost became one cluster.
    - *Here:* shows which groups of characteristics the most-played games combine more often than the clusters' sizes would suggest.
    - *Caution:* values are low partly *because* the clustering separated these tags; they describe this split, not independent evidence that the groups are unrelated.
    - The full entry also cautions that only links at or above the minimum shared games count, that under Lift the shared-game ratio is not tied to the clustering and can exceed γ, that across different γ you divide by γ, and that the ratio is neither a similarity of the games nor a cause.
  - Connection Share, as agreed:
    - *In short:* of all the link weight leaving a cluster, the part that goes to one other cluster.
    - *Higher →* more of this cluster's outside links go to that partner; a cluster's shares add up to 1.
    - *Here:* shows where each group of characteristics' overlaps with the rest go.
    - *Caution:* big clusters take large shares just by being big; use the Connection Ratio to judge strength.
    - The full entry states the pool's share as the one special case.

### Cluster connections view

**One home per selection: the Inspector.** The matrix and the card give an overview and select; they never show detail.

#### Inspector

- **The Cluster's Connections section** (after Games): one row per partner.
  - Sorted by Connection Ratio high to low, ties by raw weight. Zero-edge partners are listed at 0, then rows with an empty ratio, at the bottom. The `one_tag_pool` row is ranked like any other and labelled as the pool.
  - Columns: Ratio (with a 0…γ bar marking 1), Share, total in the Clustering Weight, links. Under Lift there are also the shared-game total and the shared-game ratio, labelled "not tied to the clustering; can exceed γ".
  - The reference line reads "1 = as their total link weight predicts; γ is the most it can reach".
  - A row selects the pair.
- **The pair view** (new):
  - both swatches and names;
  - the Connection Ratio with γ;
  - both Connection Shares, the total and the link count, plus the shared-game total and ratio under Lift;
  - the reference line;
  - "Links between them": the tag in each Cluster, shared games and Lift, sorted by shared games. Links hidden by Hide links below are marked "hidden from the drawing". A row selects that link.
  - An empty ratio says which of the three cases applies.
- **The link Inspector**: a link between two Clusters offers "show this pair". A link opened from a pair's list shows "← C1 ↔ C2".

#### Connections matrix (Cluster quality tab, full width)

- **Cells**: **Ratio** (the default, symmetric) or **Share (row → column)**, where each row adds to 100 %. This is a view choice that resets to Ratio when the dataset changes. Under Lift the shared-game ratio appears only in the cell tooltip and the pair view, never as a cell mode.
- **Colour**: one continuous ramp, `#c9ced8` to `#3b2f6b` (the Edge Appearance value ramp), fixed to 0…γ (Share: 0…100 %). A key strip marks 1 and γ. No bands or thresholds. A value a hair above γ takes the darkest colour and keeps its number.
- **Order**: label order C1, C2, …, with `one_tag_pool` last as "pool".
  - The diagonal is hatched and shows the Cluster's tag count. The pool–pool cell holds the "between one-tag clusters" row.
  - The pool's row header is inert, as it is not a Cluster. Its cells select.
- **Selection**: a cell selects the pair, and a row header selects the Cluster. The selected cell and the selected Cluster's row and column are marked. The tooltip gives every number of the pair.
- A **Matrix | Table** toggle keeps the existing `cluster_connections.csv` grid, with its five new columns. Its rows select the pair too. Matrix is the default.
- **Many Clusters**: the matrix scrolls inside the tab with sticky headers, and cells stay at least 40 px. No grouping or cut-off.

#### Cluster map card

- A "Cluster map" toggle in the canvas's top-right overlay opens a floating card. Like the Edge appearance card, it is a transient overlay.
- **What it draws**:
  - one bubble per Cluster, with area by tag count, at its tags' centroid (Global) or its region's centre (Cluster-separated), nudged apart;
  - the pool as a grey bubble labelled with its tag count, not clickable;
  - only the pairs that have a link, 0.6–7.6 px by ratio / γ, in `#3b2f6b`, with the selected pair in the selection blue.
- **Selection**: a bubble or link selects the Cluster or pair. Any selection lights up in the card, with the ratio written on the selected pair and on the selected Cluster's links.
- The card is redrawn in the browser on a layout or Network State change. Whether it is open is not kept across sessions; it stays open for the session.

#### Canvas

- A pair dims every other tag and link and fits to both Clusters, like today's Cluster focus.
- The pair's links keep their Edge Appearance colour mode and become opaque (one colour darkens them). This holds in the Cluster-separated layout too, where links between Clusters are faint.
- Links hidden by Hide links below stay hidden.
- A Cluster selection keeps today's dim-and-zoom, plus its matrix row and card bubble. Partners are not shaded by ratio.
- A selection survives a layout switch.

#### Numbers on screen

- Ratio to 2 decimals.
- Share as a whole percent, with one decimal below 1 %.
- Totals in the Clustering Weight's own format: shared games whole, Lift to 1 decimal.
- Bulgarian follows the Interface Language rule. The CSV keeps fractions at full precision.

#### Architecture

- The matrix is one escaped HTML block (`data-html`, like the Inspector's long tables), rendered by the existing Cluster quality callback from the rows it already has. No new callback.
- The recompute also writes those rows to a small `cluster-connections` store. `graph.js` draws the card from it, with the positions it already holds.
- A pair is one new selection kind, `pair`, through the same event path as region taps, whether it comes from a cell, a card link, a table row or a ranking row. Its Inspector view is built on the server like the others. The canvas highlight is a `graph.js` restyle.
- No new canvas payload. Nothing is re-sent for a highlight.

#### Guide

- In `02-app-controls.md` the Cluster quality entry gains **Connections matrix** and **Cluster map** paragraphs.
- The Inspector entry gains the Cluster's **Connections** section and the **pair view**.
- Every Ratio and Share header and tooltip points to the Connection Ratio and Connection Share anchors.
- "Connections matrix" and "Cluster map" are UI names in the guide, not CONTEXT.md terms.

### Games within a Cluster

- **Game set**: every game in the Network State (after the Minimum Months Filter) that has at least one of the Cluster's Tags. There is no threshold, and a game is not assigned to a single Cluster. Hidden, removed and below-minimum tags are never Cluster members, so only visible members can match.
- **Lead line**: "**94** of 100 games have at least one of its 18 tags". For a One-Tag Cluster: "**N** games have its tag".
- **Ranking**: matched-tag count, high to low, then Rank (Mean Monthly Players, most successful first). Rank is unique, so there is no further tie-break.
- **Columns**: Rank · Name · Matched · of its tags · Tags.
  - **Matched** is shown as "7 / 26".
  - **of its tags** is matched ÷ the game's own tags in the Tag Network. Hidden, removed and below-minimum tags don't count. It is shown as a whole percent and is never a sort key.
  - **Tags** lists the matched tags in full, wrapping, in the Members table's order (◆ Center first, then by game-set distance). It is never truncated; the real maximum is 16.
  - There is no AppID column.
  - One-Tag Clusters drop Matched and Tags (always "1 / 1" and the one tag), leaving Rank · Name · of its tags.
- **Placement**: a **Games** section of the Cluster Inspector, after Members and before Connections.
  - It shows the first `GAMES_SHOWN` (10) rows, then "Show all N" in a `<details>`, the tag view's pattern.
  - It is one escaped HTML block (`data-html`). Rows are inert.
  - There is no list for `one_tag_pool` or for a pair.
- **Clustering Weight**: none of these numbers depends on it.
- **`cluster_games.csv`**: a new additive table in the Workbench export zip, in English.
  - One row per Cluster (Multi-Tag and One-Tag, never the pool) × matching game, ordered by Cluster label, then by the on-screen ranking.
  - Columns: `cluster` (str), `appid` (int), `name` (str), `rank` (int), `matched` (int), `cluster_size` (int), `network_tags` (int: the game's tags in the Tag Network), `share_of_game` (float, matched ÷ network_tags, full precision), `matched_tag_ids` (int_list, member order), `matched_tags` (str_list, matching).
  - Each column is declared in `schema.py` and indexed in `guide_index` and Appendix B.
  - Open Network State… checks it like every other table (`recorded_table_hashes_match` recomputes it). Older exports without the file still open.
- **Guide**: the Inspector entry in `02-app-controls.md` gains the **Games** section ("Matched" and "of its tags" are explained there). The export entry in `04-files.md` and Appendix B gain `cluster_games.csv`.
- No new CONTEXT.md term: this is CONTEXT.md's "a game **has** a Tag", counted over a Cluster.

### Exports and the schema version

- **One shared `SCHEMA_VERSION` bump, from 3 to 4**, covers the five `cluster_connections.csv` columns and `cluster_games.csv`. Issue 17 makes the bump, and issue 21 adds its table under version 4.
- Exports stay English in every language: CSV columns, `selection_report.md`, JSON and the Build's `report.html`.
- No language or appearance setting reaches an export, a `state_id` or a cache key.

#### Guide slice conventions

Every G slice follows these, beyond the term table:

- **Same structure as the English file**:
  - every heading at the same level, in the same order;
  - every heading ends with `{#<english-slug>}`, including headings no code refers to;
  - every link keeps its target;
  - code spans, formulas, column and file names stay as they are.
- **Entry headings** give the English term once, in parentheses before the id.
- **In short blocks and entry markers** use the Bulgarian label set, with the same labels in the same order, and stay within the 60-word cap.
- **Numbers in prose** follow the on-screen Bulgarian rule (0,42; 12345; 42%), so the sentences `selection_text` renders appear verbatim. Numbers inside code spans, formulas and quoted column values keep their English form.
- **A partly translated file**: the slice writes its `##` sections into `bg/<file>` in the English order. Sections not yet translated are absent, and the app shows the English section in their place (issue 11).
- **The text translated** is the English file as it stands when the slice starts. An English edit made later fails parity for that section, and that is the signal to update it.

#### Strictness ratchet

- The completeness tests keep a **done-list** of catalogue modules and of guide files or `##` sections, in one place (`tests/i18n_done.py`).
- Each slice adds its own entries. From then on, a missing or orphaned entry inside them fails.
- The methods-paragraph verbatim test runs in Bulgarian once A4 and G10 are both on the list.
- **G10 deletes the done-list**, and completeness is then checked everywhere.

#### Visibility and the release gate

- The EN | BG switch is visible and plain from issue 10. There is no preview badge and no flag. Missing text falls back to English.
- **Release gate**: issue 10 adds a step to `docs/releasing-an-app-bundle.md`: "No release while `tests/i18n_done.py` exists". Nothing is released from `bilingual-cluster-views` before G10. G10 deletes the file, and with it that step, because the strict tests then do the job.

#### Review (HITL)

- **R1, calibration**, after A1–A4 and G1:
  - The researcher reads the app in BG in all three modes, and G1 in Markdown, for tone, register and terms.
  - A follow-up AFK issue applies the corrections. G2–G10 wait for it, so a systematic fault is caught in one slice, not ten.
- **R2, final**, after G10: the whole of `docs/user-guide/bg/` in Markdown, plus a last pass through the app in BG. Its follow-up AFK issue applies the corrections.
- The researcher marks corrections however they like (inline edits or a notes list).

#### Corrections flow through the term table

- A term change edits `bg-terms.md` first. The new word goes into the table, and the old word goes into its **Avoid** cell and into a new **Superseded words** section.
- A test (issue 22) scans `src/steamstudy/i18n/bg/` and `docs/user-guide/bg/` for every Superseded word and fails on a hit, which forces the sweep.
- Each Superseded entry is a stem matched at the start of a word, case-insensitively (`\bсийд\w*`), with an optional allowed-phrase list (e.g. *откриване на общности*).
- The section starts with the unambiguous misspellings: *Жакар*, *Лайден*, *сийд*, *билд*.

### Resolved while writing this spec

These choices were implicit in the tickets and are made explicit here.

- **The scan reads Superseded words, not the Avoid column.** [Bulk translation slicing and review](issues/09-bulk-translation-slicing.md) said to scan every Avoid word. The Avoid column holds ordinary words that are correct elsewhere: *филтър* is in the Minimum Months Filter's own term, *параметри* is in "Избор на параметри", and *мрежа* is the Tag Network. Scanning them would fail on correct text. The scan therefore reads a short, deliberate list that grows with each correction. The ticket's Comments record this.
- **The release gate is added at the start, not by G10.** A gate added only when it is satisfied would guard nothing. Issue 10 adds it, and G10 removes it together with the done-list.
- **The Avoid-word test and the new terms** come before the bulk slices (issue 22), so all slices start with the same table. The A slices can run in parallel, so "the first slice to add Bulgarian" was not one fixed slice.
- **Cookie names**: `steamstudy_lang` and `steamstudy_edges`, both written client-side. The server reads `steamstudy_lang` when it serves the layout.
- **The done-list** lives in one file, `tests/i18n_done.py`, which the parity tests import.
- **Order of the mechanism issues**: help and guide lookups (issue 11) come right after the core (issue 10), because `help` is called from every view module. The module wiring then runs as a chain (12 → 13 → 14), because changing a view function's signature touches `callbacks.py` each time.
- **The Interface language guide entry** in `02-app-controls.md`. No ticket placed the switch in the guide, but every control has an entry.
- **`GAMES_SHOWN` = 10** is a constant in `view.py`.
- **Numbers in Bulgarian guide prose** use the on-screen rule. The verbatim test compares sentences rendered by `tx.num`, so the guide must agree with the screen.
- **A partly translated guide file** shows the English `##` section in place of each missing Bulgarian one, so a reader never meets a gap while the slices run.
- **Older exports still check out.** `recorded_table_hashes_match` compares every table on the columns the original export has, so a version 3 export, with four connection columns and no `cluster_games.csv`, still matches its recomputation.

## Out of scope

- Features 3 and 4 in the Parameter Selection mode's Pair Inspector or in Analysis Report mode.
- Translating exports, the CLI, the Running Guide, the release checklist or the Build's `report.html`.
- Translating Steam tag names, game titles, Genre values, cluster labels or dataset labels.
- A game as a selection kind (highlighting its tags on the canvas).
- Rank scaling for edge widths, colour bands or thresholds for the Connection Ratio, and an r/γ column.
- Any language beyond English and Bulgarian. The mechanism allows one, but nothing here prepares it.
