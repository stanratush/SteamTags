# Map: Steam Success Study

Label: wayfinder:map

## Destination

An **implementation-ready spec** for (1) a resumable Steam data-collection pipeline producing five Top-100 Datasets (Overall, Puzzle, RPG, Strategy, Simulation) ranked by Mean Monthly Players, (2) the per-dataset feature analysis, and (3) a local Python-backed interactive Tag Network app, with every methodological and architectural decision locked so implementation can begin without further design questions.

## Notes

- **Domain**: academic research on commercial Steam games (comparison with educational/STEM games comes later, in a separate effort). Glossary: [CONTEXT.md](../../CONTEXT.md). Use its terms.
- **Skills**: grilling tickets → `grilling` + `domain-modeling`; research tickets → `research` (findings in `research/`); architecture → also `codebase-design`; UI → `prototype`.
- **Tracker**: local markdown (no git repo). Research findings live in `.scratch/steam-success-study/research/` rather than on `research/*` branches.
- **Standing constraints** (from the brief, apply to every ticket):
  - Never fabricate data; never bypass anti-bot protection; respect source terms.
  - **Source Substitution** (any source other than Steam Charts / SteamDB) requires explicit researcher confirmation.
  - Missing Months stay missing; no zeros before release or for gaps.
  - Exclusion rules and genre-tag list live in config files; every excluded game records its exact reason.
  - Manual filtering in the app never modifies source datasets.
  - Frequency/correlation is never presented as causation; no auto-generated semantic cluster names.
  - Reproducibility: fixed configurable seeds, snapshot timestamps and config stored in every export.
- **Settled while charting** (2026-10-03, see CONTEXT.md for definitions):
  - Score = mean of monthly Steam Charts "Avg. Players" over post-release months with data in the latest complete 60-month window (Oct 2021 – Sep 2026); Release Month (first Steam Charts month that is not a Placeholder Row) included.
  - No minimum-months rule for ranking; `months_observed` reported; the app has a Minimum Months Filter that drops games (no backfill).
  - "Has tag" = anywhere in the displayed store tag list. Tag datasets use the exact tag only.
  - Exclusions: non-`game` app type; adult sexual content; software tags; Dating Sim. Not Mature/Gore/Violent; never Education. Exact rules and lists: see [Exclusion and genre-tag config contents](issues/09-exclusion-genre-config.md).
  - Genre (feature analysis) = Steam store developer genre field. Network hide/show uses a separate configurable Genre Tag list.
  - Free-to-play included, flagged `is_free`.
  - App: local Python-backed web app; loads only the pipeline's own Top-100 export CSV; Louvain (default) or Leiden (optional mode) with fixed configurable seed and γ shown in UI and stored in exports (see [Silhouette space and cluster-quality metrics](issues/10-silhouette-cluster-quality.md)).

## Decisions so far

<!-- one line per resolved ticket -->

- [SteamDB access and tag/metadata alternatives](issues/02-steamdb-access.md): SteamDB forbids scraping without emailed academic permission (no API, Cloudflare); Steam first-party sources (store page tags + `appdetails`) cover every field but are a Source Substitution needing sign-off.
- [Steam Charts compliant access and coverage](issues/01-steam-charts-access.md): no terms/robots/API (not permission, but no rule broken); one HTML page per app gives the full monthly Avg./Peak table; gaps are absent rows; some 0.00 placeholder rows precede release; ~14–17 h at 1 req/5 s.
- [Candidate pool enumeration sources](issues/03-candidate-pool-sources.md): the full Steam Charts `/top` listing (~12.7k–13.7k apps, down to 0 current players, includes declined/delisted games) is the natural pool; never truncate it by current players; cross-check with SteamSpy and Best of Steam lists.
- [Official Steam tag taxonomy extraction](issues/04-steam-tag-taxonomy.md): official category table removed from Steamworks (Wayback 2026-05-08: 13 categories, 400 tags); live GetTagList has 446 tags; Dating Sim = 9551, Education = 1036 (also a store genre); Puzzle is not a store genre; candidate exclusion lists proposed; match on tagid.
- [Graph clustering and quality methods](issues/05-graph-clustering-methods.md): recommends Leiden (modularity objective, not the CPM default) over Louvain; Jaccard-on-game-sets distance for silhouette (unavailable with <2 clusters; report singletons separately); modularity vs. null-model baseline; Jaccard medoid as center; full removal sweep ~74 s on synthetic data, so on-demand/background + seed-noise floor.
- [Python web app stack for the tag network](issues/06-web-app-stack.md): recommended Dash 4 + dash-cytoscape + dash-ag-grid with background callbacks; dash-cytoscape is stale (Jul 2024, unfixed Dash 4 bug), so gate on a Windows spike; fallback Panel + Tabulator + custom Cytoscape.js.
- [Data source selection and substitution sign-off](issues/07-data-source-signoff.md): Steam store confirmed for tags (store page) and details (`appdetails`); SteamDB only as a permission-gated Top-100 cross-check; Steam Charts at a configurable rate (default 3 req/s), store at 1 req/2 s, no browser emulation, hard stop on challenges; raw responses kept, only Top-100 exports published; games with no store data excluded but can be added back through a sourced Manual Metadata Entry; full run waits for the operator reply and the ethics check.
- [Candidate pool definition](issues/08-candidate-pool-definition.md): pool = every Steam Charts `/top` row, size reported not enforced; N listing passes (default 2) unioned; no cross-checks in v1; store data only for scored apps at a configurable rate; new `no_tags` exclusion; completeness report with counts, pass stats and a depth check.
- [Exclusion and genre-tag config contents](issues/09-exclusion-genre-config.md): tag lists as `tagid`+name, matched on tagid against a `GetTagList` snapshot; global tag rank limit (default 20) with per-tag overrides; adult content = Steam "Adult Only" notice, descriptor 3 or `Hentai` (mainstream games with nudity stay in); software list confirmed, `Gaming` kept; Dating Sim only, tightened after the impact report; `manual_exclusion` and `exclusion_override` lists (ship empty); Desktop Companion and sexual tags are Content Flags; Genre Tags = 11 Top-Level Genres; all store genres reported with a `kind` column; all reasons recorded; pre-freeze impact report published.
- [Feature-analysis definitions](issues/13-feature-analysis-definitions.md): full Top 100, one count per game; tag/genre frequency tables with an Eligible Pool baseline and `share_ratio`; combinations up to a configurable size and `min_support` (defaults 3, 10); phi/lift/Jaccard associations with Fisher p + per-dataset BH q (descriptive only); clusters = the network's own clustering on shared defaults; defining tag out of analyses; CSVs + metadata JSON + templated report with a causal-word test.
- [Tag network app interaction prototype](issues/14-tag-network-app-prototype.md): two modes, a Workbench (A: controls / graph / inspector / tabbed tables, panels collapsible) and an Analysis report (C: numbered scrolling sections), sharing one state; shared network defaults: min games per tag 8, min shared games 8, Genre Tags and defining tag hidden, isolated tags kept as one-tag clusters; node sensitivity only on a button press; graph layout switch Global / Cluster-separated (non-overlapping cluster regions), moving nodes without reclustering.
- [Pipeline architecture and export schema](issues/15-pipeline-architecture.md): one `uv` package `steamstudy`; Collect (resumable, writes an immutable Snapshot: gzipped raw responses + SQLite request log as checkpoint) cut from an offline, deterministic Build (Snapshot + TOML config → all five datasets, reports, analysis); retry/hard-stop table; Manual Metadata Entry schema (tags-only entries allowed for `no_tags`); `top100_<dataset>.csv` contract; `snapshot.json`/`build.json` provenance; test Snapshot (4 listing pages + edge-case AppIDs) and a code-enforced full-run gate.
- [Placeholder rows and the Release Month definition](issues/16-placeholder-rows-release-month.md): any Avg 0.00 / Peak 0 month row is a Placeholder Row: not data, wherever it sits; Release Month = first non-placeholder row; every other recorded value stays (incl. tiny pre-launch months); `Last 30 Days` skipped, unknown labels/duplicate months are parse errors; unscored count split three ways; new `placeholder_rows.csv` and diagnostic `release_month_check.csv` (store date vs. Release Month, default > 3 months).
- [Dash + dash-cytoscape Windows spike](issues/17-dash-cytoscape-windows-spike.md): every check passed on Windows (Dash 4.4.1, dash-cytoscape 1.0.2 with Cytoscape.js 3.28.1, dash-ag-grid 35.3.0): node/edge taps, background progress + cancel, rapid toggling, preset-layout switching on one instance, no #229 error, no CDN in production mode; soft spots: ~55 ms redraws at ~5,000 edges, ~800 KB `elements` updates with AppIDs inline, ~4 s spawn per background job.
- [Interactive graph visualization alternatives](issues/20-graph-visualization-alternatives.md): keep Dash and treat the renderer as replaceable; if worst-case smoothness matters, wrap Cytoscape.js 3.34 (WebGL mode, still a "preview") ourselves rather than switch renderer, since dash-cytoscape (bundling 3.28.1) cannot use WebGL; fallbacks sigma.js 3 + graphology, then AntV G6 5; keep AppIDs server-side to cut the payload.
- [Alternative app frameworks and graph renderers (Python or JS/TS backend)](issues/21-app-frameworks-and-renderers.md): nothing beats Dash on facts; JS has no ready weighted Leiden and can't reproduce the Python report's clusters (Pyodide neither), so a TS front end only works as a hybrid over the Python `network` package; NiceGUI/Shiny are the Python alternates; Dash's ~4 s per job is per-job spawn, avoidable with a long-lived worker at the cost of DIY progress/cancel.
- [Web stack selection](issues/18-web-stack-selection.md): v1 = Dash 4 + dash-cytoscape 1.0.2 (pinned exactly) behind one renderer module, WebGL upgrade only if the first test Build feels slow; Python 3.14 pending a spike re-run (fallback 3.13); offline, `127.0.0.1` only; AppIDs server-side, fetched on click; seeded `spring_layout` positions computed in Python once per dataset + Minimum Months Filter and reused, Re-layout button, x/y exported; sensitivity as a Dash background job (~4 s start accepted), cache in `<build>/app_cache/`.
- [Edge weight used for clustering](issues/19-edge-weight-for-clustering.md): edge weight stays the shared-game count everywhere; new Clustering Weight setting, `shared_games` by default (config, report) with optional `lift` (N = games after the Minimum Months Filter; lift < 1 edges kept) selectable in the app; clustering, quality metrics, layout and sensitivity follow the mode; `strength_shared` + `strength_lift` always; edges export both `shared_games` and `lift`.
- [Silhouette space and cluster-quality metrics](issues/10-silhouette-cluster-quality.md): Louvain (NetworkX) stays the default with Leiden (leidenalg, modularity objective, pinned dependency) as an optional `algorithm` mode; disconnected Louvain clusters flagged, not split; γ = 1.0 (app 0.1–3.0); Jaccard game-set silhouette only, mean over Multi-Tag Clusters, n/a with fewer than 2; clusters counted "k multi-tag + s one-tag"; Q with a bipartite game–tag shuffle null (R = 20, z-score); per-cluster edge/weighted density, conductance, cut weight, plus a cluster × cluster connection table.
- [Cluster center and centrality measures](issues/11-cluster-center-centrality.md): Cluster Center = Jaccard medoid (mode-independent, works on disconnected clusters), ties → more games → lower tagid; only clusters of 3+ tags get a center and the ◆; `top_strength_tag` shown beside it with a `center_is_top_strength` flag; new node metrics `n_games`, `degree`(`_intra`), `medoid_score`, `is_center`, `within_z`, `participation` (active weight); no betweenness/closeness/eigenvector/PageRank.
- [Dash spike re-run on Python 3.14](issues/22-dash-spike-python-314.md): every spike check passes on Python 3.14.8 with the same Dash-stack versions; igraph/leidenalg load and seeded Leiden is identical across runs and versions, so the 3.14 pin stands; per-job startup matches 3.13 (~2.5 s import) only with bytecode compiled; the app must open `127.0.0.1` (not `localhost`, ~300 ms per callback) and read/write files as UTF-8 explicitly (cp1251 locale).
- [Node-removal sensitivity method](issues/12-node-removal-sensitivity.md): new term Removal Sensitivity; per tag, a cold-restart remove-and-recluster reading (ΔQ, Δsilhouette, Δk/Δs, ARI, centers lost) plus a fixed-partition reading (ΔQ, Δsilhouette); Seed-Noise Floor of K = 10 seeds, flagged at 2√2·SD or ARI below the lowest seed ARI (screening flag, not a test); all visible tags or one, by strength, no cap, estimate first, no multiprocessing; partial runs cached and resumable; sorted by ARI; the Build also writes a per-dataset sensitivity CSV.

## Not yet specified

- **Known limitations section**: tags are a current snapshot, not historical; Steam Charts coverage gaps; delisted games (`store_data_unavailable` / `no_tags` exclusions and manual add-backs); a `game`-type pool possibly under 10,000; ties at rank 100; community-voted tags include joke votes (e.g. Dating Sim on Banana); content-descriptor ids 3/4 have no official label documentation; Dating Sim rank cannot separate dating sims from romance-heavy farming sims (handled by overrides); store data depends on the researcher's country (region-locked apps, recorded country in `snapshot.json`); builds made with `--allow-parse-errors` are never published; tiny pre-launch Steam Charts months are kept as real data; Steam Charts pauses tracking of low-player apps (gaps mean the app wasn't tracked, not zero players); `release_month_check.csv` is noisy for Early Access games (see [Placeholder rows and the Release Month definition](issues/16-placeholder-rows-release-month.md)). Removal Sensitivity uses one main-seed run per removed tag; its `beyond_noise` flag is a screening aid across many tags, not a significance test (see [Node-removal sensitivity method](issues/12-node-removal-sensitivity.md)).

## Out of scope

- Comparison with educational/STEM games (later effort; the export format should not preclude it).
- Ranking by peak players; paid-only dataset variants.
- Re-ranking/backfilling games inside the app; loading arbitrary CSV schemas.
- Hybrid app stack (FastAPI over the Python `network` package + a Vite/TypeScript front end): a possible later version of the app; v1 is Dash. See [Web stack selection](issues/18-web-stack-selection.md).
- Candidate Pool cross-checks (SteamSpy top-100 lists, Valve Best of Steam "Most Played", hand-picked declined-games list): dropped from v1 by the researcher; see [Candidate pool definition](issues/08-candidate-pool-definition.md).
